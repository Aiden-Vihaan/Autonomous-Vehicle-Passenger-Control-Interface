Randomization and Counterbalancing

Project: Autonomous Vehicle Passenger Control Interface
Status: Design framework v1
Date: 22 September 2026

---

1. Purpose

If participants experience more than one experimental condition, the order in which conditions are presented may influence their responses.

For example, participants may:

- learn what the experiment is testing;
- become familiar with the interface;
- remember previous explanations;
- become more comfortable with the vehicle;
- develop expectations about future events.

These effects can create systematic differences between conditions.

Randomization and counterbalancing will therefore be considered before the final experiment is implemented.

---

2. Condition Order

The primary conditions are:

- A — No explanation
- B — Minimal explanation
- C — Contextual explanation

If a within-subject design is selected, participants should not all receive these conditions in the same order.

---

3. Candidate Counterbalancing

For three conditions, the six possible orders are:

1. A → B → C
2. A → C → B
3. B → A → C
4. B → C → A
5. C → A → B
6. C → B → A

Participants can be assigned to these sequences as evenly as practical.

The final assignment method will depend on the final number of participants and scenarios.

---

4. Scenario Randomization

Scenario order should also be randomized or counterbalanced where practical.

Example:

Participant 1:

«SCN-01 → SCN-02 → SCN-03 → SCN-04»

Participant 2:

«SCN-03 → SCN-01 → SCN-04 → SCN-02»

The exact sequence should be generated using a reproducible randomization procedure.

---

5. Avoiding Confounding

Randomization should prevent explanation condition from becoming systematically associated with:

- one specific scenario;
- one specific event;
- one position in the experiment;
- one particular difficulty level.

For example, contextual explanations should not always appear in the most visually simple scenario.

---

6. Participant Assignment

If a between-subject design is selected, participants should be assigned to explanation conditions using a predefined allocation procedure.

Where practical, allocation should be approximately balanced across conditions.

---

7. Reproducibility

The randomization procedure should be documented.

If software is used to generate condition order, the following should be recorded:

- software/tool;
- randomization method;
- seed where applicable;
- generated assignment;
- date of generation.

This allows the experimental procedure to be reproduced.

---

8. Practice Trial

A practice trial may be used to familiarize participants with the interaction method.

The practice trial should not reveal the experimental manipulation more than necessary.

Practice data should be separated from experimental data.

---

9. Learning Effects

Potential learning effects include:

- recognizing the explanation structure;
- anticipating the correct answer;
- remembering previous scenario events;
- learning the questionnaire;
- becoming familiar with the interface.

These effects should be monitored during pilot testing.

---

10. Final Decision Rule

The final randomization and counterbalancing strategy will be selected after:

1. choosing within-subject or between-subject design;
2. finalizing the number of scenarios;
3. determining the number of experimental trials;
4. conducting the sample-size/power analysis;
5. evaluating practical recruitment constraints.

No final participant assignment scheme will be claimed before these decisions are made.
